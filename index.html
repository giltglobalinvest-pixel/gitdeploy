🚀 Schnellstart in 5 Schritten
  1. Airtable Base anlegen
    → Klick auf "+ Neue Base in Claude" Link beim neuen Projekt
  2. Tabellen mit Feldern anlegen
    → z.B. "Notizen" mit Feldern: id, title, content, ...
  3. In GitDeploy: Neues Projekt
    → Name, Repo, Base aus Dropdown auswählen
  4. User anlegen + Anleitung kopieren
    → Mitarbeiter Keys generieren, Anleitung in Claude-Projekt einfügen
  5. App entwickeln + Deploy
    → Claude entwickelt mit Anleitung, HTML hochladen via GitDeploy

🔐 Sicherheit – Zwei-Token-System
🔓 READ-Token (im App-Code eingebaut)
Kann nur lesen, eingeschränkt auf Master-Base. Sicher zu veröffentlichen.
🔒 WRITE-Token (nur in GitDeploy + Airtable gespeichert)
Wird nach erfolgreichem User-Login an die App übergeben. Niemals im Code!
🔑 USER-Key (persönlich pro Mitarbeiter)
Mitarbeiter geben ihren Key beim App-Start ein. Du verwaltest sie in GitDeploy.
🔄 Was passiert beim App-Login
1. Mitarbeiter öffnet App ↓ 2. Login-Screen: persönlichen Key eingeben ↓ 3. App prüft (mit READ-Token): "Gibt es User mit diesem Key + status=aktiv in der App-Base?" ↓ 4. Wenn ja → Lade aus Master-Base/Keys: - WRITE-Token (zum Speichern) - Anthropic Key (für KI) ↓ 5. App ist nutzbar! User-Session in localStorage

💡 Wichtige Tipps
  • Token-Sicherheit: Tokens werden im Browser localStorage gespeichert, nie im Code.
  • Versionsverwaltung: Jeder Upload erstellt eine neue Version – ältere bleiben verfügbar.
  • User deaktivieren: Statt löschen → status auf "inaktiv" setzen. So bleibt die Historie.
  • Updates: Apps prüfen bei Start ob neue Version auf GitHub – Banner mit Download-Hinweis.
  • Lokale Nutzung: Apps funktionieren auch lokal (HTML-Datei doppelklicken) – Airtable hat kein CORS.
  • Free Plan Limit: 1.000 Records pro Base – pro App eigene Base = mehr Speicher.
